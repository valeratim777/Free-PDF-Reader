# PDF Reader

Бесплатный просмотрщик и редактор PDF: веб (GitHub Pages), Windows/macOS/Linux (Electron), Android (Capacitor). Документы обрабатываются только на устройстве.

- Стек: Vite + TypeScript без фреймворка; просмотр — `pdfjs-dist`, запись PDF — `@cantoo/pdf-lib`; тесты — vitest в `tests/`; линтера нет.
- Код: `src/viewer` (страницы, жесты), `src/annotations` (пометки), `src/export` (сохранение PDF), `src/translate` (перевод), `src/features` (сохранение, скан, закладки, «Назад», нативные функции), `src/ui` (панели), `src/i18n.ts` (русский/английский); `electron/` — компьютер; `android/` — Android (свой плагин `FilesPlugin.java`).
- Команды: `npm ci`, `npm run dev`, `npm test`, `npm run typecheck`, `npm run build` (сначала `tsc`, потом `vite build`).
- Выпуск: пуш в `main` обновляет веб-версию (`.github/workflows/pages.yml`); тег `v*` собирает и публикует приложения (`apps.yml`); текст выпуска — `.github/release-notes.md`, версия — в `package.json`.

## Рабочая схема «director + limits»

### Всегда
- Отвечать на языке: **русский**.
- Скилл **`director`** (`.claude/skills/director/SKILL.md`) — с начала каждой сессии: состояние проекта в `docs/00_STATE.md`; главный чат решает, проверяет, оценивает и отчитывается, а фичи, тесты, сборки, ревью делают исполнители в отдельных облачных сессиях.
- Скилл **`limits`** (`.claude/skills/limits/SKILL.md`) — перед многошаговой работой: поиск → `Explore` (Haiku), долгие команды → `runner` (Haiku), ревью → `reviewer` (Sonnet), фича → `feature-builder` / сессия на Sonnet; брифы самодостаточные, отчёты короткие.
- **Минимальная оценка 9/10** по «Готово, когда» брифа: ниже — вернуть на правки, не сдавать.
- **Проверять до сдачи** и называть, какие проверки прошли: установка `npm ci`, тесты `npm test`, типы `npm run typecheck`, сборка `npm run build`, новые тесты на новую логику, для UI — скриншоты экранов (скрипт на Playwright против `npm run dev`; готового e2e-набора в проекте нет) на ширине телефона и десктопа, без новых предупреждений.
- **Финальный отчёт пользователю**: ветка/PR (`main`), цифры проверок, лист скриншотов, что слабо, что решить ему.
- Ветки: одна фича = одна сессия = одна ветка `<ветка>-<этап>`; параллельно не больше 2, без пересечения файлов.
